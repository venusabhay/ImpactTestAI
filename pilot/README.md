# pilot/

Evidence from running the analyzer against real repositories and real
changes — not product documentation (see [`PILOT.md`](../PILOT.md) at
the repository root for how to *run* the pilot) and not engineering
design reasoning (see [`docs/`](../docs/README.md) for that).

- **[`cases/`](cases/)** — individual demonstration and pilot-round
  results: a specific real change, analyzed, with its report and
  (where applicable) audit JSON and supporting fixtures. Includes
  single milestone demonstrations (e.g. `verify-cache-change-report.md`)
  and grouped rounds (e.g. `user-management-app-pilot/`,
  `2026-08-28-pilot-round/`).
- **[`investigations/`](investigations/README.md)** — evidence gathered to
  answer a specific engineering question before deciding whether to
  build something, e.g. "how often does X actually happen across real
  repositories."
- **`reports/`** — cross-cutting summary/final reports that don't belong
  to one single case (milestone acceptance records, final round-up
  reports).
- **[`PILOT_FEEDBACK_TEMPLATE.md`](PILOT_FEEDBACK_TEMPLATE.md)** — the
  blank template used to collect structured feedback after a pilot
  round; see it filled out in, e.g.,
  `cases/2026-08-28-pilot-round/PILOT_FEEDBACK_2026-08-28.md`.

**What doesn't belong here:** anything auto-generated by a CI run or an
ad-hoc local invocation that hasn't been deliberately reviewed and kept
as a record — that belongs in [`artifacts/`](../artifacts/README.md)
instead (or nowhere, if it's disposable). Material here is curated: it
was intentionally kept because it demonstrates or investigates
something, not because a run happened to produce it.
